# Security policy

Please do not open a public issue for a vulnerability or suspected data exposure.

Use this repository's **Security** tab to submit a private vulnerability report. Include the affected revision, file or route, impact, and a minimal reproduction. Do not include live credentials, booking references, personal data, or other secrets in screenshots or logs.

If a secret or personal detail appears in Git history, assume deleting it from the current branch is insufficient. Revoke or rotate credentials first, keep the repository private, and follow GitHub's sensitive-data removal process for branches, pull-request references, cached views, action artifacts, forks, and clones.
